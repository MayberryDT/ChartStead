# 05 — Speaker portal from an applied acceptance

**What to build:** A secure speaker portal that exposes the durable speaker, event-participation, session, and onboarding work created by an applied Decision Course Check.

**Blocked by:** Course Check 01 — Single Decision Course Check tracer.

**Status:** done

- [x] A speaker can open a secure signed portal and see the relevant proposal, acceptance state, session, profile, tasks, and deadlines.
- [x] Co-speakers receive distinct portal access to the records produced for their event participation.
- [x] The portal clearly distinguishes current profile information from event-specific participation information where needed.
- [x] Revoked or expired portal links fail safely.
- [x] Applying, revising, or compensating a Decision Course Check updates portal-visible truth without exposing Course Check evidence or audit data.
- [x] Acceptance tests verify signed access, co-speaker authorization, current-versus-event history, compensation visibility, and absence of committee/private leakage.
