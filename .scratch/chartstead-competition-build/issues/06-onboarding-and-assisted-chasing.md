# 06 — Onboarding and assisted chasing

**What to build:** A speaker-onboarding workflow in which speakers maintain profiles and complete requested work while organizers see missing information, lateness, readiness risks, and editable reminder drafts without autonomous escalation.

**Blocked by:** 05 — Acceptance cascade and speaker portal.

**Status:** ready-for-agent

- [ ] A speaker can edit biography, headshot, and other allowed profile fields from the portal.
- [ ] A speaker can complete organizer-created forms and upload or replace requested files.
- [ ] The portal keeps incomplete tasks prominent and retains completed work in history.
- [ ] An organizer can create tasks with instructions, due dates, assignees, and completion requirements.
- [ ] The organizer view shows who is missing what, days until or past due, readiness flags, and last contact.
- [ ] Co-speaker details and employer approval can be represented as explicit tasks or readiness flags without altering proposal decision state.
- [ ] An organizer can generate or prepare a reminder draft containing the relevant missing work and deadline context.
- [ ] The organizer can edit, discard, or explicitly send the draft; creating it never sends automatically.
- [ ] Send attempts and outcomes append to communication and task history.
- [ ] Authorization tests protect speaker files, private task data, and other speakers' portal records.
- [ ] Acceptance tests cover task completion, file replacement, overdue prioritization, draft preparation, explicit send, and failure retention.
